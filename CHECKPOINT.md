## CP19: validated adaptive large-read transfer (PR #16)

- Base: merged CP18 `main` at `a11073dbad8bd1a54cce7cf62f9e8dc04735b450`. [PR #16](https://github.com/yaelysia/dsh-wsl-workspace/pull/16) merged at **`b18cd30f6aa079c7702199a64e903927b65f3df9`** after all **10/10** applicable CI workflows completed/success, with verified code/test head `97f2bcf63a5419e4435e194d05a525d5bda8565b`. The later CP19 checkpoint addition is **documentation only**, not a new runtime modification.
- Cause: large native reads paid two nested Base64/JSON transfers. CP19 preserves the bounded existing RPC protocol and adds an optional read-only `dataZ` zlib-level-1 receipt for `fs.read`, `fs.range`, and `fs.snapshot` (also used by `streamText`). Under 64 KiB, always use the original raw format. At/above 64 KiB, first/middle/last 8 KiB must each shrink at least 20%, and the full compressed payload must also be 20% smaller; otherwise return the **original raw receipt**. The Node consumer strictly validates Base64, raw byte length, caller cap and maximum decompressed output. The 16 MiB file-content cap, cancellation, version/guarded-write checks and stock write/edit path are unchanged.
- Measured on **real Windows→WSL2** with 3 alternating warm-up pairs + 20 alternating measured pairs, identical Linux fixtures, full data equality assertions: 256 KiB highly repetitive source P50 **11.320 → 2.687 ms** (4.21×); 4 MiB highly repetitive source P50 **148.565 → 17.469 ms** (**8.50×**), P95 **163.766 → 18.901 ms**; 4 MiB `streamText` **138.662 → 36.849 ms** (3.76×). The actual Node-received 4 MiB RPC stdout was **7,456,742 → 47,308 bytes**, about 99.37% smaller on this synthetic compressible fixture; RPC count did **not** decrease (single reads 1→1, streaming 18→18). Linux 4 MiB source P50 **54.295 → 8.205 ms** (6.62×).
- Neutral/negative controls are retained: 4 KiB Windows P50 **1.157 → 1.181 ms**, 4 MiB random binary **179.288 → 181.749 ms** (P95 **189.568 → 202.674 ms**); mixed data and compressible-header/random-body remain in the raw encoding path, with no general speedup claim. Results apply to *highly redundant code-like text*, **not** arbitrary source files, live Desktop UI, model latency or all binary content.
- [CP19 detailed method, complete latency/transport tables, error/cancellation boundaries and evidence](docs/performance-cp19.md). [Linux + Windows WSL2 native-RPC and paired CP18 benchmark](https://github.com/yaelysia/dsh-wsl-workspace/actions/runs/39883727913) finished successfully, along with [WSL1/WSL2 source/lib checks](https://github.com/yaelysia/dsh-wsl-workspace/actions/runs/39883728573), [native-files](https://github.com/yaelysia/dsh-wsl-workspace/actions/runs/39883727705), [read-snapshot](https://github.com/yaelysia/dsh-wsl-workspace/actions/runs/39883727693), read-batch, grep/read, traversal, wildcard pruning, reported Loader and persona. The `checks` WSL2 source-shell job initially failed two unrelated session-shell assertions and passed on retry **attempt 2**; the read-snapshot Windows job initially failed Ubuntu mirror package-size validation before any test ran, then passed after re-running only its failed job. Neither was waived. Original **209-error TypeScript baseline** unchanged. CP19 Desktop hands-on acceptance is not yet recorded.

### Delivered behavior

- A provable literal-directory prefix from glob patterns is passed as data to the existing Linux find script. Unrelated subtrees are pruned before their files become traversal/transport candidates. The original physical search root, headers, final matcher, sorting, VCS rules and nested-symlink no-follow behavior remain. Negative or uncertain prefixes retain broad traversal. Grep is unchanged.
- Native listDir opens its parent once and uses fresh descriptor-relative metadata for ordinary entries instead of rewalking their common ancestors. Symlinks still receive physical resolution and target metadata. Parent inode/physical-path replacement is detected before returning. No file content or metadata cache survives the call.
- Directed queries no longer encounter permission failures inside unrelated pruned subtrees. Explicit root and traversed-directory errors remain. Enumeration can return FS_STALE_VERSION if its parent is replaced; it is not an atomic snapshot of all changing children.

### Measured result, not an inferred blanket speedup

Windows-to-WSL2, 24 alternating samples after three warm-up pairs, full returned results equal on the same disk fixture:

| Operation | CP13 P50 ms | CP14 P50 ms |
|---|---:|---:|
| Shallow directory, 24 entries | 2.718 | 2.431 |
| Deep directory, 2,000 entries | 131.896 | 26.675 |
| Fixed-prefix glob | 153.668 | 14.135 |
| No-fixed-prefix control | 153.076 | 154.603 |

The first glob scenario has 120 selected .tsx files plus 16,000 irrelevant .tsx files. Returned search candidates fall from 16,120 to 120; raw stdout payload from 1,180,805 to 9,405 bytes. These are decoded search payload bytes, not a physical wire trace. For the deep enumeration, actual os.lstat calls fall from 26,012 to 24 while one fresh stat per entry remains. The no-prefix control has no gain. All P95s, Linux results, full methodology and artifact digests are preserved in the final evidence document.
